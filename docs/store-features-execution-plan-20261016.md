## ترتيب التنفيذ (شريحة صغيرة في كل مرة)

1. **المرحلة 1 — تجربة معزولة:** إنشاء صفحة برومبتات مجانية بـHTML/CSS/JS محلي فقط، مع بحث وتصنيف ونسخ سريع. لا روابط في القائمة العامة، لا Sitemap، وnoindex حتى اعتماد إطلاقها. هذه أول شريحة عمل في الفرع الحالي.
2. **المرحلة 2 — تنظيم المجاني:** مراجعة /tools/ و/guides/، وإضافة وصول أوضح إلى الموجود عند موافقة صاحب المتجر؛ لا صفحة موارد تكرر الكتالوج.
3. **المرحلة 3 — تجربة ومعاينة:** إبراز التجارب الحرة الموجودة وحالات التحميل وتوضيح الفرق بين التجربة والشراء. لا معاينة لأي منتج مدفوع مخفي، ولا طلب شراء أثناء الإيقاف.
4. **المرحلة 4 — مساعد اختيار بسيط:** ثلاثة اختيارات عن نوع الحاجة -> اقتراح رابط داخل القسم المناسب فقط، دون API أو تعقب أو رسائل إدارية للعميل.
5. **المرحلة 5 — تحسين المفضلة:** مراجعة وظائف script.js القائمة واختبار استدامة localStorage، empty states، keyboard وARIA في الوضع التجاري المستقبلي؛ دون إظهار بطاقات منتجات أثناء التوقف.
6. **المرحلة 6 — مقارنة المنتجات:** واجهة قابلة للتفعيل لاحقًا فقط بعد إلغاء الإيقاف بتصريح مستقل، وبالاعتماد على data/products.json كمرجع وحيد. لا قاعدة بيانات ثانية.
7. **المرحلة 7 — تحسين البحث العام إذا احتجناه فعلاً:** بعد قياس التجربة، لا دمج لكل الأقسام في كتالوج واحد؛ كل قسم يحتفظ بالتنقل والهوية الخاصين به.

## ضوابط إلزامية

- لا تغيير لـ data/storefront-mode.json أو /products/ أو data/products.json أو robots.txt أو sitemap.xml أو GitHub Pages/Cloudflare.
- لا إظهار أسعار أو أسماء أو صور المنتجات المدفوعة المخفية، ولا روابط إلى /products/ من المسارات الجديدة.
- لا تعديل لـ header.js أو footer.js أو الصفحة الرئيسية قبل الموافقة على تجربة المستخدم.
- لا كود من APK خارجي: محتوى المكتبة وتنفيذها أصليان وخفيفان.
- لا تسجيل دخول ولا APIs ولا اشتراكات ولا خدمات خارجية. لا تحميل خطوط أو مكتبات أو صور عن بعد.
- احترام تفضيل تقليل JavaScript وتجنب حركات الواجهة غير الضرورية.
- أي تغييرات في واجهة العميل تكون بسيطة وبالعامية المصرية حيث تلائم القسم؛ لا رسائل إدارية للزوار.
- مراجعة PRs القديمة في الأقسام المستهدفة قبل أي تعديل جديد، خاصة طلبات التصميم/الصفحة الرئيسية القائمة.
