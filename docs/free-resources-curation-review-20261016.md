# مراجعة تنظيم الموارد المجانية — 16 أكتوبر 2026

## الهدف

تجهيز صفحة دخول بسيطة للموارد **دون إتاحتها رسميًا أو خلط أقسام المتجر أو إعادة نشر منتجات تجارية مخفية**.

## المنفذ في الفرع

- `/resources/`: فهرس موارد ثابت لا يحتاج JavaScript إضافي، ويعمل دون API أو اشتراك.
- يعيد استخدام أنماط مكتبة البرومبتات الموجودة أصلًا ويضيف CSS محليًا صغيرًا.
- 3 مجموعات من الموارد المتاحة: البرومبتات والكتابة، الحسابات والمخزون، السيرة الذاتية.
- 5 روابط فقط إلى الملفات والأدوات المجانية الموجودة (لا نسخ من الحاسبات أو محتوى البرومبتات).
- رابط تحميل Calculator Suite Free يظل داخل `/tools/` (نفس مصدر الملف، لا رابط جديد قد يختلف عن الإصدار المعتمد).
- لا تعديل لصفحة المتجر الرئيسية أو أدواته أو هيدر الأقسام أو الـRegistry أو ملفات المنتجات.

| القسم | الوجهة الفعلية |

| مكتبة البرومبتات | `/resources/prompts/` |
| حاسبة التسعير | `/tools/pricing-calculator/` |

## عائق يجب علاجه قبل إدراج الأدلة

فحصت `/guides/` على `main` يوم 16 أكتوبر 2026: ملفات صفحات الأدلة الـ29 كافة تحتوي روابط HTML تشير إلى `/products/` رغم حالة إيقاف المنتجات. لذلك **لم أضف أي دليل** إلى الصفحة الجديدة، ولم أستنسخ نصوص الأدلة، ولم أحرر الأدلة القديمة في هذا الطلب لمنع تكرار إصلاحات PRs على staging.

قبل إدراج أي دليل في الفهرس: مراجعة PRs التي تعالج روابط الأدلة الموجودة، تنظيف رابط البيع/المنتج المخفي من صفحة الدليل الفعلية، اختبار عدم ظهور أي روابط منتجات تجارية مخفية، ثم إضافة الدليل في مراجعة منفصلة بعد موافقة صاحب المتجر.

## بوابة النشر

- إعداد `data/storefront-mode.json` ما زال `productsVisible:false` ولا يتغير.
- `resources/index.html` و `resources/prompts/index.html`: `noindex,nofollow`.
- لا روابط للموارد الجديدة في `header.js` أو `footer.js` أو `sitemap.xml`.
- `qa/free-resources-qa.mjs` يتحقق من الروابط الخمسة، الصفحات الموجودة، خلوها من روابط المنتجات المخفية، عدم إضافة أدلة غير مُنقحة، وعدم إدراج صفحات المسودة في Sitemap والروابط العامة.
- أضفت تشغيل QA هذا إلى `.github/workflows/store-qa.yml` على طلبات السحب.
- لا دمج أو نشر مقصود. **تنبيه تقني:** موقع الإنتاج يعمل من GitHub Pages على `main`؛ دمج أي PR على `main` يؤدي عادةً إلى نشره تلقائيًا. لذلك الاعتماد على PR مسودة فقط حتى قرار الإتاحة الفعلي.
- قبل أي إطلاق رسمي: فحص الواجهة على عرض 320، 390، 768، 1440، مراجعة الصفحة يدويًا، تحديد روابط إدخال الصفحة في التنقل وقرار الفهرسة بوضوح، والحفاظ على فصل الأقسام.
